# Kame32 Android controller

Native Android application for the eight-byte BLE pose protocol in `../fw`. Android 8.0+
(API 26), with no third-party runtime libraries. Open this folder in Android
Studio, let Gradle sync, and run the `controller` module on a BLE-capable phone.
Use JDK 17 or newer supported by Android Gradle Plugin 9.4.1, Android SDK 35,
and Gradle 9.6.0 (the included wrapper).

```sh
./gradlew :controller:assembleDebug
```

APK: `controller/build/outputs/apk/debug/controller-debug.apk`.

1. Power the robot and enable Bluetooth on the phone.
2. Tap **Scan for Kame32**, grant Nearby Devices permission (location permission
   and enabled system Location on Android 8–11), then select the robot's address.
3. Move a slider or tap **Apply all 8 servos** to send all eight displayed positions.
   The slider values are requested values, not measured servo positions.
4. **Set all to 1500 µs** moves all eight channels to their midpoint.
5. **PWM OFF • turn ON** applies all eight displayed values and keeps them active.
   **PWM ON • turn OFF** releases all outputs.
6. **STOP** releases all outputs. A slider or Apply All enables them again.

To play a gesture, set the sliders, enter the step hold time in milliseconds,
and tap **Add displayed pose**. Repeat for each step, then tap **Play gesture**.
The app holds the final pose. Tap **STOP** or **Stop gesture and release servos**
to end playback and release PWM. Applying a manual pose also ends playback.
Recorded steps are kept in memory for the lifetime of the controller screen.

### Update the robot firmware

The robot needs an OTA-capable firmware build installed over USB first.
In the app, tap **Choose firmware file** and select the Kame32
`firmware.bin` generated by PlatformIO. Connect to the robot, tap
**Install firmware over BLE**, and hold its **BOOT** button while confirming
**Install**. Release BOOT when the sending progress appears. Keep the app in
the foreground until Kame32 restarts, then scan and reconnect. **Cancel update**
disconnects and aborts an unfinished transfer.

Physical PCA9685 channels 0–4 and 12–14 use the firmware's 500–2500 µs range.
The app sends one eight-byte BLE write with response per pose and refreshes the
active pose every 500 ms. Connection setup and writes
have a five-second watchdog. Firmware independently releases outputs after two
seconds without a pose refresh. Leaving the app disconnects BLE and releases outputs;
returning requires a new connection and an explicit movement command. Connecting
sends an all-zero pose to release outputs. No pairing needed.

Before testing with attached linkage, verify each servo's usable pulse range.
On real hardware, check all eight channels, a gesture with different hold times, Stop during playback, Bluetooth loss,
permission denial, and leaving/returning to the app. Verify firmware timeout by
interrupting app communication. Compilation cannot validate radio or servo motion.

## Wi-Fi setup

Connect over BLE, tap **Wi-Fi settings**, and enter the name and password of
your 2.4 GHz Wi-Fi network. Tap **Save and connect** and accept Bluetooth
pairing if prompted. When the ESP32 joins, tap **Open servo web page**.
Use **Check Wi-Fi status** to retrieve its address after reconnecting.
